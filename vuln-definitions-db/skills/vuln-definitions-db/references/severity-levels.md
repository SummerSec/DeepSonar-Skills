# 定级条款：VRT P1–P5 → 四档 + 数据库领域条款

本文件为 **数据库领域（DBMS 引擎与数据库云平台）** 的定级规则。
ClickHouse Bugcrowd 项目按 **Bugcrowd VRT** 定官方档；本表把 VRT 顶层优先级映射为本仓四档，并给出数据库语境的判定条款。

> 语义基线：[Bugcrowd VRT](https://bugcrowd.com/vulnerability-rating-taxonomy) + [ClickHouse 项目页](https://bugcrowd.com/engagements/clickhouse)（对照日 2026-08-28）。
> VRT 具体条目优先于本表的顶层映射；两条冲突时按 VRT 条目，并在 `rationale` 写明。
> 与全局 `severity-levels.md` / `<type>.md` 冲突时，**数据库语义以本文件为准**。赏金表 **不** 改档。

---

## 1. VRT 顶层映射

| VRT | 本仓映射 | 一句话 | ClickHouse Bugcrowd 赏金（OSS / Cloud·Langfuse） |
|-----|----------|--------|----------------------------------|
| P1 | `critical` | 未认证远程可直达的沦陷级后果 | $1050–1250 / $2100–2500 |
| P2 | `high` | 重大数据 / 权限突破，一般前提 | $500–625 / $1000–1250 |
| P3 | `medium` | 有限影响或需多前提 | $50–300 / $100–600 |
| P4 | `low` | 轻微或复杂前提 | $0–50 / $50–100 |
| P5 | `none` | 信息性 / 项目不收 | 无 → 不报 |

**纪律**：走本插件的正式 finding `severity` 为 `critical|high|medium|low`（P1–P4）；P5 不是低危，是 **不报**（`reportable: false`）。不要把第四档写成 `none`，也不要用 `none` 冒充 P5。

---

## 2. 权限前提 × 影响矩阵

| 影响 \ 前提 | 未认证远程 | 认证受限用户 / 普通成员 | 恶意租户（云，跨 org） | 管理员 / 本地 OS |
|-------------|------------|--------------------------|------------------------|------------------|
| OS 级任意代码执行 | **C1** | **H1** | **C4** | 不报（自伤） |
| 任意数据 / 全库读写 | **C2** | **H2** | **C3** | 不报 |
| 服务器 / 集群接管 | **C2 / C4** | **H8** | **C3 / C4** | 不报 |
| 有限信息泄露 | M1 | M1 | M2 | 不报 |
| 仅资源耗尽 / 崩溃 | 排除（DoS） | 排除（DoS） | 排除（DoS） | 不报 |

- **列（前提）比行（影响）先看**：同一技术缺陷，前提不同档位不同
- 「本地 OS 管理员可读配置 / 密钥」不是漏洞；「受限 SQL 用户能读到」才是
- 云平台目标必须先问：**同租户还是跨租户**（跨租户几乎必抬一档）

---

## 3. 严重（P1 → critical）

| # | 判定条件 |
|---|----------|
| C1 | 未认证远程代码执行：无凭据网络可达 clickhouse-server（HTTP / native TCP / Interserver）或云平台公网接口，执行任意代码 |
| C2 | 认证绕过：无凭据获得任意账号（含管理员）会话；云平台登录绕过或账号接管 |
| C3 | 跨租户沦陷：云平台 A 租户读写 B 租户数据、接管 B 租户服务 / 资源 / 集成凭据（含 BYOC 边界） |
| C4 | 受限用户 → 系统沦陷：readonly / granted SQL 用户或云平台普通成员，突破到 OS shell、服务器管理员或集群管理面 |
| C5 | 未认证可达的稳定内存破坏：默认 / 常见配置下任意 SQL 或协议输入可稳定控制执行流（RCE 前置原语） |

---

## 4. 高危（P2 → high）

| # | 判定条件 |
|---|----------|
| H1 | 认证受限用户 RCE：需 SQL 账号（或云普通成员），但实现 OS 级任意代码执行（UDF / 表函数 / codec / 字典等链路） |
| H2 | 权限模型绕过：受限用户访问未授权库 / 表 / 行 / 列 / 聚合数据（GRANT 语义、row policy、列掩码、settings profile） |
| H3 | SQL / 查询注入：控制面或查询接口拼接输入，可读敏感数据、绕过权限或写入 |
| H4 | 云平台同租户越权：普通成员管理他人资源、改他人配置、读 API key / 计费 / 集成凭据 |
| H5 | SSRF 实害：控制面功能（webhook / 集成 / 私有端点）可打内网或云 metadata，窃取凭据或触达内部管理服务 |
| H6 | 可接管级凭据泄露：泄露密钥 / 令牌可直接接管服务、账号或云资源（secrets 类） |
| H7 | 存储型 XSS 打他人：控制面存储型 XSS 可窃取其他用户 / 管理员会话（POST 反射 / self-XSS 被项目排除） |
| H8 | 复制 / 集群协议认证绕过：跨节点凭据伪造或节点冒充，网络可达前提下可接管集群写入 / 元数据 |

---

## 5. 中危（P3 → medium）

| # | 判定条件 |
|---|----------|
| M1 | 有限信息泄露：非敏感元数据、内部路径 / 堆栈、低敏配置、不可利用的 system 表信息 |
| M2 | 云平台低敏 IDOR：他人非敏感对象（名称、计数、通知偏好等） |
| M3 | 需多项前提的权限绕过：需管理员主动误配置 + 特定交互才可达 |
| M4 | 会话 / 令牌缺陷：可利用但影响有限（仅延长有效期、登出后残留等） |
| M5 | 备份 / 导出 / 日志配置缺陷：部分数据暴露，非全量敏感数据 |
| M6 | 盲 SSRF：可探测内网但不能读响应、拿不到凭据 |

---

## 6. 低危（P4 → low）

| # | 判定条件 |
|---|----------|
| L1 | 复杂前提的低敏越权：需受害者高度配合（多次交互 / 异常操作序列） |
| L2 | 自身账号内的配置缺陷：无跨用户影响但有轻微安全含义 |
| L3 | 有限 UI / 逻辑缺陷：带轻微安全含义（注意：纯「缺安全头 / 版本披露」已被项目排除，不是低危） |

> 项目排除项（缺限速、缺安全头、版本披露、EXIF 等）**不落在 P4**，直接 `reportable: false`——见 `adjustment-and-invalid.md`。

---

## 7. 定级纪律

- 先走 `gates.md`：**威胁模型 → 资产范围 → 环境合格 → 安全实害 → 可复现**
- `severity_rule` 填本文件锚点，如 `severity-levels.md#H2`（或 `database.md#H2`）。另填 `db_class`、`target_asset`、`vrt_priority`；可选 `bounty_eligible`
- 与 CVSS：本文件定性；量化用 `vuln-scoring`（默认 v3.1）。CVSS **不得**单独抬档
- **边界情况对照 `history-patterns.md` §3 定级校准**：未认证受限控制流原语无完整 RCE 也 High（K1）；需高权限 + 特殊配置的 RCE 链仍 High（K2）；同用户跨角色缓存污染默认低档（K3）；superuser 功能误报不报（K5）。命中校准点时在 `rationale` 写 `history-patterns.md#K_`
- **不收录具体 case**：无 CVE / issue 清单
