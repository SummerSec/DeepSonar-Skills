# runtime-harness — 真机动态验证

## 目标

在 **不破坏用户数据** 的前提下，用真机/模拟器验证静态候选的可达性与影响；产出可复核的复现步骤 + logcat + 截图。

## 章节

### 1. 设备准备（默认未 root）

- 优先未 root / 未越狱设备或官方模拟器；root 仅当授权且候选明确依赖时，并在报告中标明前提  
- 关闭不必要的自动备份；使用专用测试账号

### 2. 安装与重置

- 卸载旧包 → 安装审计包 → 记录 versionCode  
- 每条高风险用例前视情况 clear 数据，避免状态串扰

### 3. adb 原语（示例级，非武器化）

- 安装/卸载、启动组件、传 extra、读 logcat、截屏、拉应用私有目录（仅 debuggable 或授权备份场景）  
- 包可见性（Android 11+ `queries` / 可见性策略）影响攻击者 App 解析，须记录

### 4. Frida（验证用）

- 仅用于确认分支到达、参数值、SSL pin 是否绕过成功（若授权）  
- **不写** 通用免杀 / 绕过加固武器化脚本；脚本最小、可审阅、绑定本包

### 5. MITM

- 仅在授权与用户同意安装用户 CA / 系统代理时进行  
- 证书固定失败时记录现象，不默认暴力卸 pin；卸 pin 须授权且写入前提

### 6. 触发策略

- 按 `candidates.md` 逐条：Deep Link → 导出组件 → Provider → bridge  
- 恶意 App / 同设备 IPC 场景配合 `poc-attacker-app.md`  
- 控制并发与重复，避免本地资源耗尽被误写成「漏洞」（INV1）

### 7. 观察点

- logcat 关键字（含自建 `POC-ATTACKER` tag）  
- 文件/SharedPreferences 变化、网络请求、界面越权数据、进程崩溃（本地崩溃单独标 INV1）

## 产出

- 每条验证：步骤列表、期望/实际、logcat 摘录、截图路径  
- 更新候选状态：已复现 / 不可达 / 需更高前提

## 陷阱

- **root 当普通用户**：前提不同档位不同（由 definitions 裁定）  
- **debug 包结论外推 release**  
- **START 成功当漏洞（INV26）**  
- **厂商 ROM 差异**：权限/导出/后台启动限制不同，注明机型与 OS 版本
