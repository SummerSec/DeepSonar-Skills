# 级别调整与无效漏洞

定级后必须过本文件：命中调整条款 → 下调或判无效；命中无效条款 → 直接停。

---

## 一、级别调整（官方 10 条）

| # | 条款 | 对本模块含义 | 实战处理 |
|---|------|--------------|----------|
| ADJ1 | 漏洞已有消减措施且无法绕过 | 缓解存在且绕不过 → 降级或判无效 | SELinux/MAC 挡死后，不报「DAC 宽」 |
| ADJ2 | 安全影响有限 | 特定版本/非核心/非敏感 → 降级或判无效 | lite-only、非核心组件、非敏感数据 → 默认不跟 |
| ADJ3 | 特权依赖 / 物理接触 | 需特权或物理接触 → 降级或判无效 | 必须先 native/SA/root/**system UID** → **直接判无效** |
| ADJ4 | 利用场景极小概率 | 依赖极小概率场景 → 降级或判无效 | 过期证、特殊时序、极窄配置、**须再叠未证明洞** → 不跟 |
| ADJ5 | 默认配置或选项造成隐患 | 依据影响酌情调整 | **默认弱才算**；App 主动 `skip` 不算 |
| ADJ6 | 需解锁 bootloader 才能本地攻击 | 不作为主利用路径 | 解锁 bootloader 不是常规攻击前提 |
| ADJ7 | 需开发者模式 / Debug 模式 | 不作为主利用路径 | 开发者模式不是常规攻击前提 |
| ADJ8 | 编译器或平台配置缓解机制 | 缓解存在 → 按绕过可能定级 | 可绕过且直达 RCE/关键泄露才报 |
| ADJ9 | 获得的信息为该权限范围内的部分信息 | 部分信息 → 降档 | 只泄露「是否已授权」等状态 → 中危降低危 |
| ADJ10 | 规格下无人被授该权限 | “缺校验”若规格本不允许任何调用方 → 不算洞 | 规格层面无人拥有该权限 → 不认定 |

**命中判定**：新发现先自查是否踩中任一 ADJ；踩中 → 降级或判无效，写明命中条款号。

### ADJ3 / ADJ4 实战补充（OH 常见话术）

以下表述一旦出现在前提里，**默认不进投递队列**（除非能证明普通三方/远程模型可绕过该前提）：

| 前提话术 | 处理 |
|----------|------|
| 利用需 **system UID** / `system_app` / root | ADJ3 → 判无效 |
| 利用需 **TOKEN_NATIVE** / 已控某 SA | ADJ3 / INV7 → 判无效 |
| 利用需 **额外再获取一个** system/内核洞 | ADJ4 → 单洞不报或按已证最低影响 |
| **SA 中继**只走到 stub，未打到目标能力实害 | ADJ4 / INV2 → 链不完整，不报 |
| 路径穿越「**结合其他漏洞**可进一步 root」 | 单洞按已证明的隔离突破（如 H3）定；不自动抬严重 |
| 官方或报告写「**受限场景 / 特定场景**」ACE，又证不出普通三方/默认可达 | 按 L1/M1 定级，不上抬 C/H |
| 远程绕过安装管控，**仍需用户一次确认** | 不按 C4/H10；无其它实害则 ADJ4 |

## 二、无效漏洞（官方明文，命中即停）

| # | 条款 | 实战处理 |
|---|------|----------|
| INV1 | 无外部攻击路径：仅系统自身/提交人自触发 | 自攻击、自注册密钥、只能搞自己进程 → 停 |
| INV2 | 没有安全影响的软件功能性错误 | 只有“代码闻起来不对”、无攻击链、**中继半链** → 停 |
| INV3 | 利用依赖钓鱼、诱导点击等社工 | 需用户配合被欺骗 → 停（允许 1 次正常安装恶意 App 的本地模型） |
| INV4 | 主要影响第三方/通用协议，应投对应渠道 | 三方库/上游内核通用 CVE → 转上游（OH 默认路径独立实害可例外） |
| INV5 | 上报前技术细节已公开 | 已公开 PoC → 不参与奖励 |
| INV6 | 重复提交 | 仅首个报告有效 |
| INV7 | 权限等价：利用所需权限本身可造成同等效果 | 已有同权权限再调接口 → 停 |
| INV8 | 仅本地触发的应用临时 DoS | ForceStop/ForceExit、**仅本应用 crash** → 停或不报 |
| INV9 | 其它应属无效场景 | 兜底 |

**复现硬门槛**：最新公开版本 + **标准默认配置** 可复现；报告须人工验证 + 分步复现 + **完整可编译 PoC**。  
「最新」指后继仓 / 当前公开 Release 的活树，不是赏金名单上停更仓的 `master`，也不是调度器冻结的旧 SHA。只在冻结树上成立、现树已修 → 不投递（对内可记历史缺陷）。只复刻冻结逻辑的 host harness ≠ 产品可复现。见 `gates.md` Gate V。

### INV4 一 / 三方边界

- **三方库、上游协议、通用内核 CVE**（官方名单里的 `third_party_*`、上游 `kernel_linux` / `kernel_linux_4.19` / `_5.10` / `_6.6` 通用树）：默认 INV4，不因公告 CVSS 高分自动生成 finding  
- **例外**：缺陷落在 OH **默认启用** 路径，普通远程或普通三方 HAP 可独立 e2e 演示实害 → 按本插件条款定级，并写明落点组件  
- **OH 内核补丁/独有模块**：`kernel_linux_patches`、`kernel_linux_common_modules*`、`kernel_common_modules_newip` 中可证为 OH 独有路径的，按在册自研，不是 INV4  
- **内核构建配置**：`kernel_linux_config`、`kernel_linux_build` 走非运行时，默认不跟  
- **名单外仓库**：不是本 bounty 资产，见 `asset-scope.md`，不投递  
- **自研 vs 三方**：类型覆盖只对照在册自研仓；不把三方条目扩进类型表

## 三、强前提迁出清单（实战规则）

以下任一成立，视为「强前提」，不进待复现队列，按无效处理：

| 类型 | 例子 |
|------|------|
| 能力前提 | 必须 TOKEN_NATIVE / SA / **system UID** / 写系统落盘路径 |
| 链式前提 | 必须先再打一个未证明的 RCE/提权；SA 中继未闭合 |
| 环境前提 | 仅 lite 产品、须 `nosharefs` 等非默认开关 |
| 场景过窄 | 仅过期证书、单独密码学卫生无链 |
| 缓解后不可达 | SELinux 等使普通路径不可用 |
| 证据未闭合 | needs_human 且链未闭合；host harness 只复刻冻结逻辑 |
| 版本前提 | 仅停更仓 / Job 冻结旧 SHA 可复现，后继仓或最新公开版本已修 |
