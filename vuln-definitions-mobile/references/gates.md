# 挖掘门禁 Gate T、S、E、C、R 与报告要求

发现可疑点后 **按顺序回答**；任一「否」→ 不进入深度 PoC，最多记对内缺陷。
形态见 `mobile-vuln-types.md`；威胁模型见 `terminology.md`；排除见 `adjustment-and-invalid.md`。

> **Gate 字母仅在本域内有效**（Mobile 用 `T`、`S`、`E`、`C`、`R`，与 db 同字母集）。不要套用其它域的字母含义（OH 的 `A`–`D` / `V`，Chrome 的 `P` 等）。

## Gate T · 攻击者是谁？（威胁模型）

- [ ] **T1** 攻击者是：远程（诱导点击）/ 同设备恶意 App / 邻近网络 MITM 之一？
- [ ] **T2** 不需要：已越狱 / root 设备、物理访问、已中毒机器、目标员工协助？
- [ ] **T3** 不需要管理员 / 用户主动做出不合理的配置（关闭系统保护、安装不可信证书）？
- [ ] **T4** 不依赖未证明的第二洞才产生安全含义？
- [ ] **T5** 用户自伤 / 自账号内影响不算（不报）

## Gate S · 是不是本插件的资产？

- [ ] **S1** 目标是 Android / iOS **应用**（APK / IPA / 应用内 WebView / 混合栈），不是系统内核 / 框架？
- [ ] **S2** 目标在目标项目页（HackerOne / Google Bug Hunters 等）的 in-scope 范围内？
- [ ] **S3** 不是官方测试域 / 非发货构建 / 模拟器专用行为？
- [ ] **S4** 不是第三方 SDK 在出货路径不可达的缺陷？
- [ ] **S5** 写清平台与版本：目标 App 版本、Android SDK 级别 / iOS 版本、最新支持版本是否受影响？

## Gate E · 环境合格吗？（复现纪律）

- [ ] **E1** 目标 App 最新支持版本（目标项目认可范围）可复现？未修？
- [ ] **E2** 用官方分发版本（Play / App Store / 官方侧载），非 debug / debuggable 包？
- [ ] **E3** 不依赖已越狱 / root、特定 ROM、特定设备型号、模拟器行为？
- [ ] **E4** 不依赖用户先安装恶意 App（若该前提本身超范围）？
- [ ] **E5** 不依赖用户主动关闭保护（安装不可信证书、开启未知来源）？
- [ ] **E6** 明确当前版本 WebView / 网络栈配置（JS 是否启用、pinning 是否生效）？

## Gate C · 有没有「安全实害」？

至少命中一条，且能演示（纯理论 / **本地 DoS** / 本地纯崩溃 / 本地杀进程 / 本地资源耗尽 **不算**，见 INV1；**入口面本身不算**，见 INV26）：

| 实害类型 | 合格例子 | 不合格例子 |
| ---------- | ---------- | ------------ |
| 代码执行 | 深链接写 `.so` 覆盖 → 进程代码执行；WebView JS bridge 反射执行 | 仅崩溃日志 |
| 账户接管 | 深链接 / URL Scheme 偷授权码换完整会话；2FA 绕过接管 | 仅理论会话拼接；URI 形态像 token 但登录流未消费 |
| 数据访问 | 组件导出 / Provider 越权读他人数据、深链接读私有文件 | 读自己的数据 |
| 凭据窃取 | MITM 窃 OAuth 令牌；硬编码 key 直接接管服务 | 仅探测 |
| 会话 / XSS | WebView 任意 URL 打登录态；存储型 XSS 窃他人会话 | self-XSS；`loadUrl` 未发生 |
| 信息泄露 | 可接管级凭据 / 敏感数据越界泄露 | 版本号、低敏元数据 |
| 可用性 | 破坏性远程 DoS：恢复出厂 / 永久删用户或 Profile / 无交互卸载 App / 干扰紧急呼叫（H8） | 本地崩溃日志、FGS 超时杀进程、本地资源耗尽（INV1） |
| 深链 / 导出入口 | 未授权敏感 sink：深链直接特权操作、URI/extra 当可信输入（WebView / 文件 / Intent 重定向 / 凭据）、OAuth 一次性码可截获、带登录态加载攻击者 URL | 仅 `exported` / 自定义 scheme / 不校验调用方 / `START` 成功 / 打开默认页或官方登录 Custom Tab（INV26） |
| 权限 / 能力滥用 | 无障碍或通知监听被滥用读屏窃取凭据（AP6）、可变 PendingIntent 越权执行（AI7）、iOS entitlements / TCC / App Group / App Extension / 生物识别绕过（IP1–IP5）、敏感数据以弱加密（ECB / IV 复用）落盘后可恢复（AS5 / ID5） | 仅声明权限 / 仅弹窗无实际访问；算法弱但密文不可恢复（INV13） |

- [ ] **C1** 危害大于攻击者已有能力（本就有权读的数据不算）
- [ ] **C2** 影响能写清到「谁、越过了哪条边界（应用沙箱 / 认证 / 授权 / WebView 进程）、拿到什么」
- [ ] **C3** 有可观测证据（界面状态 / 文件落盘 / 请求回显 / OOB），不是「可能」

## Gate R · 能否复现并合格投递？

- [ ] **R1** step-by-step 复现步骤（含 App 版本、平台版本、设备、配置差异）已写？
- [ ] **R2** PoC 是最小化的（深链接 URL / Intent / HTTP 请求 / 恶意页面），可独立复跑？
- [ ] **R3** 测试遵守目标项目纪律：无扫描器、限速、只用自己测试账号？
- [ ] **R4** 没有触碰他人数据 / 账户（只测自己账号）？
- [ ] **R5** 发现 PII 泄露或 shell → 已停止深入、立即上报（停止条款）？
- [ ] **R6** 报告含：漏洞描述、复现步骤、影响、平台与版本、截图 / 流量证据、修复建议？
- [ ] **R7** 已写清 `prereq`（user_click / non_latest_version / rooted / 等）与 `subject_revision`？

## 决策

```
Gate T 不过     → 非威胁模型，停
Gate S 不过     → 非本插件资产 / 排除面，停
Gate E 不过     → 环境不合格（越狱 / 非发货构建 / 已修）→ 对内或停
Gate C/R 不过   → 无安全实害或不可复现，停
全过            → 四档定级（critical/high/medium/low），可写正式 finding
```

## 报告要求（对齐 HackerOne 移动端项目惯例 / Google Bug Hunters 设备项目规则，供已授权投递）

1. **描述 + 步骤 + 影响**：漏洞描述、触发入口（深链接 URL / Intent / URL Scheme / 网络请求）、复现步骤、潜在影响
2. **平台信息**：App 版本、OS 版本、设备型号、网络环境（若涉及 MITM）、WebView / 网络栈配置
3. **证据**：流量截图 / 文件落盘证明 / 界面状态 / PoC 页面或脚本（最小化）
4. **不写完整武器化 exploit**；验证路径即可
5. **AI 辅助报告**须人工核威胁模型 + 可达 + PoC；批量低质量按刷屏处理
6. **协调披露**：公开须目标项目方批准
7. **目标项目为 Google Bug Hunters 的 Android 与 Google 设备项目时**（规则与资格见 `google-android-devices-rules.md`）：
   - 须在合格硬件（Pixel / Nest / Fitbit）的 **最新公开可用构建** 上复现；设备 90 天内到 EOL → 不报
   - 首报必须带功能性 PoC，以 **机器可读附件** 提交（`.zip` / `.md` / 可执行脚本）；纯 UI 交互类可用高质量录像 + 分步说明替代
   - **内存破坏类必须**附补丁或根因代码修复；framework / 逻辑类强烈期望附补丁（非强制）
   - 纯理论、未最小化 fuzzer 崩溃、只占时间戳的 shell 报告 → 关闭且不奖；报告须从提交起可行动
   - 对照已发布威胁模型 / known non-bugs 清单后再提交；低信噪比会触发自动限速
   - 系统层目标（AOSP framework / 内核 / TEE / bootloader / 固件）档位来源换 `vuln-definitions-oh`，程序规则仍走本行

**禁止**：未授权目标、扫描器、超限速、破坏真实用户数据、发现 PII / shell 后继续深入。
