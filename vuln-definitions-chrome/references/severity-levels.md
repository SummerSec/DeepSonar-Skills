# Chrome 四档危害定义

本文件是 Chromium 官方四档的 **可引用条款**。  
口径：[Severity Guidelines](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/security/severity-guidelines.md)（对照日 2026-08-23）。  
定级时从上到下匹配：命中最高且证据充分的一级；证据不足则降级。  
每档给出 CVSS **区间（近似）**（精确分用 `vuln-scoring`，默认 v3.1、可按需 v4.0；不替代本文件定性）。

> 本仓报告模型：官方「Critical S0→critical、High S1→high、Medium S2→medium、Low S3→low」。  
> 官方四档均可写入正式 finding。非安全漏洞与 Gate 不过不报（`reportable: false`），**不要**把低危写成 `none`。  
> `severity: low` 是官方低危档；`confidence: low` 仍禁止（两字段勿混）。  
> `Security-Impact_None` **仍按本文件定级**，只是不走常规修复 SLO。

| 档 | 本仓映射 | 官方 | 修复优先级（官方） | CVSS Base 区间（近似） |
|----|----------|------|--------------------|------------------|
| 严重 | `critical` | S0 | P0；目标 30 天内全量；野外部署可 7 天公开 | ≥ 9.0 |
| 高危 | `high` | S1 | P1；目标 60 天内全量 | 7.0 – 8.9 |
| 中危 | `medium` | S2 | P1；当前 Stable，可延到下个 Stable 合并 | 4.0 – 6.9 |
| 低危 | `low` | S3 | 初值 P3；通常不合入 Stable/Beta；满 30 天对 committer 可见 | 0.1 – 3.9 |

**野外已武器化或正在被利用**：不论本档是哪一级，修复优先级按 **P0、7 天或更快** 处理。这只改优先级，不自动改 `severity`。

---

## 1. 严重（Critical / S0）

攻击者能以 **用户完整权限** 读或写底层平台上的任意资源（文件系统、注册表、网络等）。

| # | 判定条件 |
|---|----------|
| C1 | **浏览器进程**（及该平台上同样未沙箱、持用户完整权限的高权进程，如 Android / Windows / Linux 的 Network）内存破坏，且网页内容可直接或间接到达 |
| C2 | **未沙箱 GPU 进程**内存破坏，网页内容可到达且**不必先沦陷 renderer**（部分平台 GPU 已沙箱，见 `process-sandbox.md`） |
| C3 | **多洞利用链**整体能在沙箱外执行代码（链上的单洞各自按较低档） |
| C4 | 网页内容可读 **任意本地文件** |

### 不是严重的情况

- 必须先已沦陷 renderer 才能打到 browser / 未沙箱 Network / 未沙箱 GPU / 内核 → **High**（H4/H7），不是 C1/C2
- 浏览器进程内存破坏但必须关浏览器或毁掉 profile → **最高 High**
- 沙箱内（renderer / V8 / 已沙箱 GPU）任意代码 → **High**（H1/H2）
- 只影响部分用户（仅 Linux、仅无障碍）→ **不因此降出 Critical**
- 链上的单洞不要单独标 Critical

---

## 2. 高危（High / S1）

攻击者能在**其它源的上下文中执行代码**、冒充其它源，或读取跨源数据。  
本应 Critical、但有不寻常缓解的，常落在本档。

### 内存安全

| # | 判定条件 |
|---|----------|
| H1 | 沙箱内任意代码执行：renderer 内存破坏 |
| H2 | 沙箱内任意代码执行：V8 内存破坏，或 V8 DCHECK 正确性失败 |
| H3 | 已沙箱 GPU 进程内的内存破坏 |
| H4 | 已沦陷 renderer 触发的 browser / 其它高权进程（该平台上未沙箱的 GPU 或 network）内存破坏 → **沙箱逃逸** |
| H5 | 已沦陷 renderer **受控读取** browser / GPU / network 进程 **≥16 字节** |
| H6 | browser / 其它高权未沙箱进程内存破坏，需要**具体但常见**的用户交互（例如授予一项权限） |
| H7 | 内核内存破坏，可被已沦陷 renderer 用作沙箱逃逸 |
| H8 | 用 MojoJS 触发的、可利用的 browser 崩溃（已沦陷 renderer 前提，通常落本档） |

### Web 平台与 UX

| # | 判定条件 |
|---|----------|
| H9 | **完全绕过同源策略**，含通用 XSS（UXSS）：可在任意源上下文执行脚本 |
| H10 | Site Isolation：跨站执行上下文**意外共享同一 renderer** |
| H11 | Site Isolation：跨站**数据泄露** |
| H12 | **完全控制**地址栏（omnibox）所显示的源 |

### 其它

| # | 判定条件 |
|---|----------|
| H13 | 标准安装下、**无额外前提**的系统权限提升 |

### 定级提示

- 沙箱逃逸的**影响**像 Critical，但官方因「已沦陷 renderer」这一前提标 High
- 必须关浏览器 / 毁 profile 的洞：**最高 High**，还可被其它缓解再降
- iframe sandbox / CSP sandbox 绕过走 H9–H11，不走 H4

---

## 3. 中危（Medium / S2）

可读取或修改**有限**信息；单独不致命但可进利用链（给内存利用用的信息泄露、可外带的敏感用户信息）。  
更高档但缓解不寻常时，可降到本档。

### 内存安全

| # | 判定条件 |
|---|----------|
| M1 | V8 **正确性**问题：不同编译层给出不同结果 |
| M2 | 内存破坏，且必须安装**某个特定扩展** |
| M3 | browser 进程内存破坏，需要**非标准命令行旗标**且要用户交互 |
| M4 | **独立沙箱的 GPU 着色器编译器**（当前：macOS Metal / `MTLCompiler`）上本应 High 的洞 |

### Web 平台与 UX

| # | 判定条件 |
|---|----------|
| M5 | HSTS 绕过 |
| M6 | 同源策略绕过，但页面必须满足**多项前提** |
| M7 | 任意页面可绕过**安全插页**（interstitial） |
| M8 | 攻击者能**稳定读取或推断完整浏览历史** |

### 其它

| # | 判定条件 |
|---|----------|
| M9 | 标准安装、无额外前提，打破操作系统所执行的 **用户/用户边界** |

---

## 4. 低危（Low / S3）

本应更高，但缓解极强或范围极窄。

### 内存安全

| # | 判定条件 |
|---|----------|
| L1 | 任一进程中**不受控的单字节**越界读 |
| L2 | renderer 内**任意**越界读（ASAN READ 除非是小尺寸读，否则按 WRITE 处理） |
| L3 | renderer 内存破坏，需要**特定交互**（例如拖拽） |
| L4 | browser 内存破坏，由**关浏览器**触发，且触发不可靠或很难 |
| L5 | 已沦陷 renderer 打到的 browser 内存破坏，还**必须关浏览器**才触发 |
| L6 | browser 内存破坏，且必须是带 **debugger 权限**的扩展 |
| L7 | browser / network / GPU 中**不受控的未初始化读**，经 IPC 传给已沦陷 renderer（对照：受控 ≥16 字节是 **H5**） |

### Web 平台与 UX

| # | 判定条件 |
|---|----------|
| L8 | 网页内容可画到浏览器 UI 之上 |
| L9 | **降低沙箱有效性**但未逃出 |
| L10 | 绕过「需要用户手势」的要求 |
| L11 | **部分** CSP 绕过 |
| L12 | **有限的**扩展权限绕过 |
| L13 | 地址栏欺骗：只能显示某些 URL，或另有缓解 |
| L14 | 非地址栏、非站点信息面板上的 UI 欺骗 |
| L15 | 能稳定读取或推断**有限**浏览历史 |
| L16 | 把重要警告藏在其它明显 UI 下面的欺骗 |
| L17 | 分栏（split-view）对话框混淆 |
| L18 | **任何形式**的 clickjacking / enterjacking（连点、按住键等）。复杂手势或多重前提 → 可用性缺陷，不是安全问题 |

### 本仓处理

- 必须会定级为低危：`severity: low`，`reportable: true`
- 非安全（INV）与 Gate 不过另标 `reportable: false`（不是低危，也不是 `none`）

## 5. 前提 × 影响 速查矩阵（浏览器向）

| 影响 ↓ \ 路径 → | 网页内容直达 | 已沦陷 renderer | 特定扩展 / 非标准旗标 / 关浏览器 |
|------------------|--------------|-----------------|----------------------------------|
| 未沙箱高权进程 ACE / 任意本地文件 / 用户完整权限 | **严重** | **高危** | 高危（关浏览器封顶）或中/低 |
| 沙箱内 ACE（renderer / V8 / 已沙箱 GPU） | **高危** | —（已在沙箱内） | 中危或低危 |
| 完全 SOP / UXSS / Site Isolation / 地址栏源完全可控 | **高危** | 高危 | 视前提降档 |
| 有限读写、完整历史、HSTS、插页、Metal 编译器 | 中危 | 中危 | 中危 |
| 单字节/renderer OOB 读、部分 CSP、弱沙箱、有限历史、一般 UI 骗 | 低危 | 低危（未初始化经 IPC → L7；≥16B 受控 → H5） | 低危 |
| 纯崩溃 / DoS / MiraclePtr PROTECTED / 不合理交互 | 非安全 | 非安全 | 非安全 |

> 矩阵按官方条款归纳；具体以条款 # 为准。  
> 「只影响 Linux / 只影响开了 a11y 的用户」**不**向右移动一格。

## 6. 影响语 → 条款映射（抽象）

将常见「路径 + 结果」说法对齐到本文件条款。用于定级辅助，**不是**历史漏洞清单。

| 影响语（抽象） | 倾向条款 | 备注 |
|----------------|----------|------|
| 网页 → browser / 未沙箱 Network 内存破坏 | C1 | 须默认可达，不是先毁 profile；Mac/Fuchsia 上 Network 已沙箱则不走 C1 |
| 网页 → 未沙箱 GPU（如 Android）内存破坏 | C2 | 先要 renderer 沦陷则走 H4 |
| 网页 → 任意本地文件 | C4 | |
| 完整链出沙箱拿到用户权限 | C3 | 单洞各自低档 |
| 网页 → renderer / Blink 内存破坏 → ACE | H1 | |
| 网页 → V8 ACE / DCHECK 正确性失败 | H2 | 不同编译层结果不一致 → M1 |
| 网页 → 已沙箱 GPU ACE | H3 | 仅 Metal 编译器 → M4 |
| 已沦陷 renderer → browser/未沙箱高权内存破坏 | H4 / H8 | MojoJS 可利用崩溃常在此 |
| 已沦陷 renderer 受控读高权进程 ≥16 字节 | H5 | 不受控未初始化 → L7 |
| 授一项常见权限后 browser 内存破坏 | H6 | |
| 已沦陷 renderer → 内核内存破坏可逃逸 | H7 | |
| UXSS / 任意源执行 | H9 | |
| 跨站进同一 renderer | H10 | |
| 跨站数据进错进程 / 被读走 | H11 | |
| 地址栏源完全伪造 | H12 | 只能骗部分 URL → L13 |
| 标准安装无前提系统提权 | H13 | 已是同用户本机 → INV（物理本机） |
| 必须装某扩展才内存破坏 | M2 | debugger 权限 → L6 |
| 非标准旗标 + 交互才打到 browser | M3 | |
| 完整浏览历史可稳定推断 | M8 | 有限历史 → L15 |
| renderer 任意 OOB 读 | L2 | ASAN READ 默认当 WRITE，除非小读 |
| 拖拽等特定手势才 renderer 内存破坏 | L3 | |
| 网页画到浏览器 UI 上 | L8 | |
| 沙箱变松但没逃出去 | L9 | |
| clickjacking / enterjacking | L18 | 复杂手势 → 非安全 |
| MiraclePtr PROTECTED UAF | INV | 功能缺陷 |
| 标签页崩溃 / CHECK / 纯 DoS | INV | FAQ：不当安全漏洞 |
| 空指针且固定小偏移 | INV | 大于 32KB 或偏移可控 → 仍评 |

**纪律**：**不得**为贴近某份 VRP 奖金表或历史 crbug 数量而抬级或压级。  
只影响部分用户不降档；罕见交互才降档。
