# component — 第三方组件 / 框架默认配置类漏洞定义

## 1. 何时使用

缺陷的 **根因在目标引入的第三方组件、框架或其默认配置**，而不是自研代码逻辑：

- 组件已知 CVE（反序列化、解析器、模板、上传组件等）
- 框架默认配置缺陷（无认证注册、无认证管理端点、Mass Assignment、默认凭证）
- 依赖清单与供应链引入面（私有源、制品仓库、构建脚本）

判据：**修复方式是升级组件、收紧框架配置或替换依赖**，而不是改自研业务代码。

---

## 2. 漏洞定义是什么

**组件 / 默认配置缺陷**：目标集成的第三方组件存在已知漏洞，或其默认配置在生产可达位置暴露特权能力。

### 判定三段（必须全部走完）

| 段 | 判定条件 |
|----|----------|
| 可达性 | 组件版本与配置在目标上实际启用，对应路由 / 端点 / 入口网络可达 |
| 攻击前提 | 是否需要已认证、是否需管理员误配置、是否需特定交互 |
| 厂商状态 | 上游是否已修复（未修复 = 无可用补丁；已修复但目标未升级 = 未修补） |

**不覆盖（边界）**：

- 仅版本号落后、无已知可达利用路径 → `none`（N1 等价，见 N1）
- 自研代码中的同类缺陷（如自己的注册接口无校验）→ `authz.md` / `logic-flaw.md`
- 仅出现在依赖清单 / SBOM 中，无调用点、无暴露路由 → `none`
- 攻击者需已是管理员或已持有等价权限 → 按前提降档，不按组件名声抬档

---

## 3. 严重（Critical）

| # | 判定条件 |
|---|----------|
| C1 | 未认证可达的组件默认配置缺陷（无认证注册、无认证管理端点、默认凭证），可直接取得管理员能力 |
| C2 | 未认证可达的组件 CVE 可造成远程代码执行或整库读写 |

---

## 4. 高危（High）

| # | 判定条件 |
|---|----------|
| H1 | 组件 CVE 在目标上可达，且可取得代码执行或数据读写（需已认证前提） |
| H2 | 框架默认配置缺陷可导致批量信息泄露（用户枚举、日志、配置、内部路由） |
| H3 | 上游未修复的可达 CVE（无补丁可用），已认证前提下可造成重大影响 |

---

## 5. 中危（Medium）

| # | 判定条件 |
|---|----------|
| M1 | 组件 CVE 可达，但影响限于信息泄露或需较强前提 |
| M2 | 组件版本落后且存在理论利用路径，未在目标上演示可达 |
| M3 | 默认配置缺陷仅暴露低敏信息（版本、路由表、非敏感开关） |

---

## 6. 无危害（None）

| # | 判定条件 |
|---|----------|
| N1 | 组件 CVE 不可达（无调用点、无暴露路由、已升级到修复版本） |
| N2 | 组件版本落后但仅出现在依赖清单，目标不加载该模块 |
| N3 | 依赖项本身是设计上公开的客户端库，且无服务端影响 |

---

## 7. 与其它类型的边界

| 情形 | 主类型 |
|------|--------|
| 组件 CVE 的利用落点是反序列化 / 注入 | `deserialization.md` / `injection.md`；本类记可达性判定 |
| 组件缺陷由目标误配置触发（默认口令、开放端点） | 本类（C1）；若由自研代码放行则归 `authz.md` |
| 私有源 / 制品仓库投毒导致下游可执行 | `cloud-native.md`（供应链面）或 `rce.md`（执行面） |

---

## 8. 白盒 / 黑盒证据要点

| | 白盒 | 黑盒 |
|--|------|------|
| 最低 | 依赖版本 + 可达调用点 / 暴露端点 | 组件指纹 + 可复现的越权或执行差异 |
| Critical | 默认配置端点无认证中间件且含特权操作 | 未认证完成管理员级操作 |
| 常见 none | 组件已升级或路由未挂载 | 仅指纹命中，无行为差异 |
