# authz — 认证与授权类漏洞定义

## 1. 漏洞定义是什么

**认证/授权缺陷（AuthN/AuthZ）**：系统未正确验证「你是谁」或「你被允许做什么」，导致攻击者执行 **超出其合法权限** 的操作，或 **伪造身份**。

本类型覆盖：

| 子类 | 含义 | 常见 CWE |
|------|------|----------|
| 认证绕过 | 未登录访问需认证资源 | CWE-287/306 |
| 垂直越权 | 低角色执行高角色功能 | CWE-269/863 |
| 水平越权 / IDOR | 访问同级其他主体资源 | CWE-639/862 |
| 会话/令牌缺陷 | 可伪造 JWT/会话、固定会话 | CWE-384/347 |
| 危险状态变更 | 无 CSRF 且导致接管级操作（边界） | CWE-352 |
| 配置面暴露 | 内部管理接口 / Actuator / 调试端点默认无认证 | CWE-306/1188 |
| 身份创建滥用 | 任意用户注册 / 登录 / 注销，无校验 | CWE-620/287 |
| 令牌可铸造 | cookie / 业务令牌无签名或签名不校验，可自造任意身份 | CWE-347/565 |
| 会话生命周期缺陷 | 改密 / 注销 / 权限变更后旧会话仍有效 | CWE-613 |
| 跨域信任配置缺陷 | CORS 反射任意 `Origin` 且带凭据；`postMessage` 无 `source`/`origin` 校验 | CWE-942/346 |
| 悬空资源接管 | 子域名 / 存储桶指向已释放资源 | CWE-350 |
| 弱口令 / 默认凭证 | 可预测口令或产品默认口令可直接登录 | CWE-1392/521 |

**成立必要条件**：

1. 存在受保护资源或特权操作  
2. 校验缺失、可绕过、或对象级授权缺失  
3. 攻击者实际获得 **不应有的能力或数据**  

**不是漏洞**：管理员在管理后台管理用户（预期能力）。

---

## 2. 严重（Critical）

| # | 判定条件 |
|---|----------|
| C1 | **未认证** 可访问管理功能或执行管理操作 |
| C2 | 可 **接管任意账户**（密码重置绕过、token 伪造、改绑手机无校验） |
| C3 | 普通用户可提升为 **全局管理员** 或等价 |
| C4 | 多租户下可 **切换到任意租户管理员** 或读写全部租户 |
| C5 | JWT `none`/已知密钥伪造 **任意身份** 且密钥固定可利用 |
| C6 | **未认证或普通用户** 可访问内部管理接口 / Actuator / 调试端点，且响应含 **可操作能力**（改配置、读密钥、执行命令）；仅返回非敏感配置则落 M6 |
| C7 | 弱口令 / 默认凭证可登录 **管理员角色**，且公网可达 |
| C8 | 会话令牌 **无签名或签名不校验**，可铸造任意用户（含管理员）身份 |

---

## 3. 高危（High）

| # | 判定条件 |
|---|----------|
| H1 | 登录用户可 **批量** 读/改他人 **敏感** 数据（证件、手机、私信、精确位置、支付信息） |
| H2 | 垂直越权到 **重要但非最高** 管理功能（审核、退款、配置部分开关） |
| H3 | 可操作他人 **高价值对象**（订单支付态、权限角色、API Key）但非全局 admin |
| H4 | 认证绕过影响 **核心业务 API**，虽非管理后台但数据面重大 |
| H5 | 弱口令 / 默认凭证可登录 **普通角色**，或管理员角色仅内网可达 |
| H6 | 改密 / 注销 / 权限回收后旧会话仍有效，且旧会话可访问他人数据 |
| H7 | CORS 反射任意 `Origin` 且 `Allow-Credentials: true`，可从第三方站点读取登录态接口响应（等价锚点：`client-side.md#H4`，同一 finding 只报一条） |
| H8 | `postMessage` 无 `origin` / `source` 校验，第三方页面可驱动敏感操作或读取敏感回包（等价锚点：`client-side.md#C2` / `#M4`，同一 finding 只报一条） |

---

## 4. 中危（Medium）

| # | 判定条件 |
|---|----------|
| M1 | IDOR 仅影响 **低敏感** 字段（公开昵称、已公开内容） |
| M2 | 仅能越权看到 **自己组织内** 非敏感统计，业务上可接受边界模糊 |
| M3 | 需复杂条件且 **难稳定复现** 的竞态提权 |
| M4 | 缺少 CSRF，但操作 **不敏感**；或已有 SameSite/双重提交部分缓解 |
| M5 | 测试账号/演示租户之间的越权，生产隔离不同（若生产同样则提高） |
| M6 | 内部管理接口未授权，但仅返回 **非敏感配置**（版本、路由表、健康检查） |
| M7 | CORS 反射但未带凭据，或响应不含敏感字段 |
| M8 | 子域名可接管，但无可用投递路径（无 cookie 域继承、无 OAuth 回调、无脚本加载） |

---

## 5. 无危害（None）

| # | 判定条件 |
|---|----------|
| N1 | 资源 **本就是公开** 的（公开资料、公开 API） |
| N2 | 对象级授权存在且正确（服务端校验 owner/tenant） |
| N3 | 前端隐藏按钮但后端拒绝 → **不是** 越权成功；若后端也放行才是漏洞 |
| N4 | 用户访问自己的资源 |
| N5 | 管理员访问管理 API（在已正确认证为管理员时） |
| N6 | 仅前端路由守卫缺失，后端 API 全面鉴权且无绕过 |
| N7 | 默认口令在首次登录被强制修改，且无绕过路径 |

---

## 6. 白盒 / 黑盒证据要点

| | 白盒 | 黑盒 |
|--|------|------|
| 最低 | 路由无中间件 / 无 ownership 检查 | 换 ID/角色后 200 且数据属于他人 |
| Critical | 全局 admin 路由零鉴权 | 未登录调用成功 |
| none | `authorize(resource, user)` 完整 | 换 ID 返回 403 |
