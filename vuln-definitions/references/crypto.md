# crypto — 密码学原语与协议完整性类漏洞定义

## 1. 何时使用

缺陷的 **根因是密码学原语、密钥使用或签名校验**，后果是 **数据完整性 / 不可否认性被破坏**，而不是读取越权或代码执行：

- 签名 / 消息认证缺失或被跳过（回调、通知、结算报文）
- 密文可被伪造或投毒（同态计算、ElGamal 等公钥原语、可延展加密）
- TLS / 证书校验被绕过（证书固定缺失、校验开关可关）
- 密钥派生 / 随机数 / 填充模式误用导致可预测

判据：**攻击者无须攻破授权模型，即可让系统接受伪造或篡改的数据。**

---

## 2. 漏洞定义是什么

**密码学原语 / 协议完整性缺陷**：系统对数据的真实性或完整性判定可被绕过或被伪造，导致错误数据被当作权威数据接受（入账、发权益、执行结算、放行请求）。

| 子类 | 含义 | 常见 CWE |
|------|------|----------|
| 签名校验缺失 / 可绕 | 回调、通知、报文未验签或开关可关 | CWE-347 |
| 密文可伪造 / 可延展 | 原语未做完整性保护，密文可构造合法伪造 | CWE-353 / CWE-347 |
| 密文可投毒 / 清零 | 计算方或被授权方可任意修改他人密文结果 | CWE-345 |
| 传输层校验绕过 | 证书固定缺失、校验可禁、信任任意 CA | CWE-295 |
| 原语误用 | 弱随机、ECB、固定 IV、可预测派生 | CWE-338 / CWE-329 |

**成立必要条件**：

1. 存在被信任的 **数据真实性判定**（签名、MAC、密文完整性、证书链）
2. 该判定缺失、可绕或原语不提供完整性
3. 攻击者可构造出被系统接受的伪造 / 篡改数据，并造成业务后果

**不覆盖（边界）**：

- 攻击者可读他人数据 → `authz.md`（授权面），本类只管「数据被伪造 / 篡改」
- 泄露密钥本身 → `secrets.md`；密钥泄露后再伪造 = 该条 secrets + 本类各一条
- 仅使用弱算法但无现实攻击者模型（无密钥已知、无密文可控）→ M1 / `none`
- 纯理论攻击、需拥有私钥或本地管理员 → 不在威胁模型

---

## 3. 严重（Critical）

| # | 判定条件 |
|---|----------|
| C1 | 可伪造 **跨用户 / 跨租户** 的密文或签名数据，破坏他人数据完整性（同态密文任意投毒 / 清零） |
| C2 | 可伪造 **资金 / 结算 / 权益** 报文（支付回调未验签、签名跳过导致响应伪造），且可重复利用 |
| C3 | 取得的伪造能力可不经原始持有者同意改变业务结果，且无其它前置限制 |

---

## 4. 高危（High）

| # | 判定条件 |
|---|----------|
| H1 | 原语可被部分操纵，影响单条记录或非资金类完整性（单条业务数据、单次校验结果） |
| H2 | TLS / 证书校验可绕，可中间人读取或改写敏感流量（需受害者网络前提） |
| H3 | 签名校验缺失但利用面受限于特定子系统，影响面可计量 |

---

## 5. 中危（Medium）

| # | 判定条件 |
|---|------|
| M1 | 实现偏差存在，但需密钥已知、本地前提或强烈假设才可利用 |
| M2 | 仅降级为弱算法 / 弱随机，未演示伪造路径 |
| M3 | 完整性保护缺失但被篡改数据不进入业务判定（仅日志、仅缓存） |

---

## 6. 无危害（None）

| # | 判定条件 |
|---|------|
| N1 | 使用成熟库且密钥管理正确、签名校验完整（含时间戳与重放防护） |
| N2 | 仅攻击者自身数据可被改动，无法影响他人或结算结果 |
| N3 | 校验缺失但数据完全来自可信服务端常量，攻击者不可控 |

---

## 7. 与其它类型的边界

| 情形 | 主类型 |
|------|--------|
| 伪造结果的根因是业务侧未校验金额 / 未做幂等 | `logic-flaw.md` |
| 签名密钥硬编码在前端或仓库中 | `secrets.md` + 本类各一条（根因不同） |
| 伪造链路依赖任意文件读写或注入 | `file-access.md` / `injection.md` |
| 仅传输层配置弱（无凭据外带、无篡改证据） | M2 或不报 |

---

## 8. 白盒 / 黑盒证据要点

| | 白盒 | 黑盒 |
|--|------|------|
| 最低 | 验签分支缺失 / 可被参数关闭；原语无完整性保护 | 可复现地提交伪造数据并被接受 |
| Critical | 伪造数据可入账或跨用户生效 | 实际完成伪造并观察到业务状态改变 |
| 常见 none | 验签 + 时间戳 + 重放防护完整 | 伪造被拒 |
