# logic-flaw — 业务逻辑 / 风控 / 计费类漏洞定义

## 1. 何时使用

目标缺陷 **不依赖注入、越权、文件等机理**，而是 **业务规则本身可被绕过**，或规则实现存在状态一致性问题：

- 支付 / 结算 / 免密扣款 / 回调校验
- 付费墙、会员上限、试用期、邀请码、配额与权益
- 风控与内容安全校验（审核、禁言、内容合规标记）
- 并发与状态机（重复领取、超发、跳步）

判据：**去掉所有技术机理，仅剩「规则可被绕过」或「状态可被重复消费」时，归本类。**

---

## 2. 漏洞定义是什么

**业务逻辑缺陷**：攻击者按 **服务端未设防的操作顺序、次数或参数组合** 使用正常功能，取得规则未授予的资金、权益、数据或状态。

### 定档轴（取命中最高的一轴）

| 轴 | 含义 |
|----|------|
| A 资金直接损失 | 可直接造成资金流出 / 收入损失，可重复、可放大 |
| B 权益 / 配额逃逸 | 付费墙、试用、会员上限、邀请码、额度限制可绕 |
| C 风控与内容合规失效 | 内容安全校验、审核、风控规则可绕 |
| D 业务状态一致性破坏 | 并发超发、重复领取、状态机跳步 |

**规模乘数**：单账号单次 = ×1；**可批量、可脚本化、可反复** = 升一档。

**不覆盖（边界）**：

- 根因是缺授权校验（接口无鉴权、换 ID 可读他人资源）→ `authz.md`
- 根因是输入进入解析器语义 → `injection.md`
- 仅影响自身账号体验、无资产与合规后果 → N1 / 不报
- 前端展示层限制而服务端同样限制且不可绕 → N1

---

## 3. 严重（Critical）

| # | 判定条件 |
|---|----------|
| C1 | 资金可 **直接损失**（免密扣款被劫持、支付回调签名不校验可伪造通知、金额可改），且可重复利用 |
| C2 | 风控 / 内容安全 **完全失效**，可批量绕过校验发布违规内容或批量通过审核 |
| C3 | 权益 / 配额逃逸可 **批量跳账号** 放大（批量注册刷取、脚本化薅取、批量领取），造成平台级可计量损失 |

---

## 4. 高危（High）

| # | 判定条件 |
|---|----------|
| H1 | 付费墙 / 配额可无限绕过（含无限叠加续期、绕过会员与数量上限），造成可计量的收入损失 |
| H2 | 风控 / 内容安全校验可绕，但需特定前提或影响面有限（单次、单条内容） |
| H3 | 并发 / 竞态可超发 **高价值权益**（优惠券、额度、库存、礼包） |
| H4 | 状态机可跳步导致越级权益生效（先激活后付费、绕过前置审批） |

---

## 5. 中危（Medium）

| # | 判定条件 |
|---|----------|
| M1 | 规则可绕但损失有限（单次、小额、需人工介入） |
| M2 | 会员 / 试用 / 数量上限可绕，影响仅限自身账号体验与少量资源 |
| M3 | 需不稳定竞态或受害者配合才能达成的绕行 |
| M4 | 内容合规标记可改但影响不可外显（仅内部评分、不对外发布） |

---

## 6. 无危害（None）

| # | 判定条件 |
|---|----------|
| N1 | 限制在前端展示层，服务端同样限制且不可绕 |
| N2 | 操作结果与规则一致（正常顺序、正常次数），无规则逃逸 |
| N3 | 仅自身账号数据被改变，无资产、权益、合规后果 |

---

## 7. 与其它类型的边界

| 情形 | 主类型 |
|------|--------|
| 绕过方式依赖接口缺鉴权（换 ID、无 token） | `authz.md` |
| 金额 / 数量可被注入改写 | `injection.md` |
| 并发超发的根因是数据库约束缺失而非业务规则 | 本类（按 H3 定档） |
| 伪造签名的根因是密码学原语或签名校验缺失 | `crypto.md` |

---

## 8. 白盒 / 黑盒证据要点

| | 白盒 | 黑盒 |
|--|------|------|
| 最低 | 服务端缺少次数 / 状态 / 签名校验分支 | 接口序列可复现地产生规则外结果 |
| Critical | 资金或权益计算完全由客户端参数决定 | 实际完成可复现的资金 / 权益逃逸 |
| 常见 none | 服务端有幂等键、乐观锁、签名校验 | 仅在自身账号产生的正常差异 |
