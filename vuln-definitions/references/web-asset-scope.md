# Web 资产范围与合格判定（asset-scope）

对 Web 目标定档前，先判定 **资产是否合格**。本文件给通用判定；目标程序自带规则文件（`vendor-<program>.md`，见 `web-vendor-rules.md`）时 **以程序文件为准**。

---

## 1. 资产分桶（`web_asset`）

| 值 | 含义 | 合格判定要点 |
|----|------|--------------|
| `core_web` | 主站 / 核心业务域（登录后主流程） | 默认合格；写清域与路径 |
| `console` | 管理后台 / 控制台 / 运营端 | 默认合格；区分「普通用户」与「管理员」前提 |
| `api_gateway` | 对外 API、开放平台、网关与回调 | 默认合格；未文档化端点同样合格（可报） |
| `static_frontend` | 前端包、静态资源、SPA 路由 | 合格主体是 **前端包内的泄露与本域执行语义**，不是 CDN 缓存策略 |
| `marketing` | 官网、活动页、帮助中心 | 仅在承载登录态、凭据域继承或用户数据时合格 |
| `mobile_webview` | App 内 WebView 承载的 Web 资产 | 应用层形态走 `mobile.md`；Web 侧机理按本插件 |
| `self_oss` | 目标自研开源项目 / SDK | 合格条件是「出货路径可达」；仅仓库内理论问题不合格 |
| `ci_runner` | 扫描节点 / 构建机 / 流水线执行环境（含平台扫描后台与本地 CI） | 合格条件是「会处理攻击者可控工件」且节点持有凭证、与其它租户共享或结果回写平台；纯自用一次性沙箱按实害降档 |
| `third_party_hosted` | 目标数据托管在第三方 SaaS | 默认不合格（责任在第三方）；仅当目标侧配置错误造成实害时合格 |
| `edge_cdn` | CDN / WAF / 反代 / DNS | 仅在其配置造成凭据暴露、缓存污染、绕过鉴权时合格 |
| `dev_tool` | 开发者本机工具（CLI / 桌面端 / IDE 插件） | 合格条件是工具会处理不可信工件；档位按受害者的交互与凭证面（见 `rce.md` §1 执行位置声明） |

---

## 2. 判定结论（`web_scope`）

| 值 | 条件 |
|----|------|
| `in_scope` | 属 §1 合格分桶，且不在 §3 范围外清单 |
| `in_scope_with_conditions` | 合格但需满足条件（如仅自建租户可测、仅指定测试账号） |
| `out_of_scope` | 命中 §3 范围外清单，或属第三方责任边界 |
| `unlisted` | 疑似目标资产但未在程序清单列出；按 `web-gates.md` 决定是否推进 |

- 未列出资产**不因「没人说不算」而合格**；推进前必须在 `rationale` 写明判定依据
- `out_of_scope` 的 finding **不报**，即使技术上成立

---

## 3. 常见范围外（通用清单）

| 面 | 状态 |
|----|------|
| 支付处理三方页面、风控三方 SDK 内部 | 第三方责任边界 |
| 目标采购的第三方 SaaS（工单、客服、监控、邮件） | 第三方责任边界（除非目标侧配置造成实害） |
| CDN 默认页 / 目录列表页 / 未绑定域名的默认 vhost | 范围外 |
| 状态页、支持工单、文档站、招聘站 | 范围外（除承载登录态） |
| 缺安全头（CSP / HSTS / cookie flag）、版本披露、目录列表 | 信息性，不报 |
| 缺限速 / 短信与邮件轰炸（无实害） | 不报 |
| 扫描器原始输出、未人工验证的告警 | 不报 |
| 纯理论问题、需物理接触 | 不报 |
| 需受害者**自行运行攻击者直接提供的可执行程序**（下载并执行 exe / 脚本、手工粘贴 payload 到自己控制台运行） | 不报（前提不现实） |
| 受害者**正常使用已有工具解析攻击者可控工件**时被利用（用已安装扫描器扫恶意仓库、IDE 打开恶意工程、播放器打开恶意样本） | **合格**，归 `ci_runner` / `dev_tool`；这是工具缺陷，不是受害者操作失误 |

## 4. 悬空资源（子域接管）

| 判定段 | 条件 |
|--------|------|
| 资源 | DNS 记录指向已释放的云资源（对象存储桶、PaaS 应用、边缘函数、包注册名） |
| 可接管 | 攻击者可完成资源创建且 **托管内容会以目标域名对外提供** |
| 投递链 | 存在可用投递路径：cookie 域继承、OAuth 回调、脚本加载、邮件链接 |
| 结论 | 有投递链 → `authz.md` 悬空资源接管条款；无投递链 → `authz.md#M8`；仅 DNS 记录残留且不可接管 → 不报 |

---

## 5. 多域与多租户边界

- 同一主域下的子域 **不是同一资产**：写入 cookie 域、执行脚本、读接口响应须逐项说明影响域
- 多租户必须写清边界值：`普通用户` / `同租户他人` / `跨租户`（`ai-agent.md` 前提轴同义）
- 跨租户影响按最高档；同租户越权按对应类型条款

---

## 6. 资产变更与活动期资产

- 临时活动域名 / 活动期接口属合格资产，前提是 **活动期内可复现** 且写入 `activity` 字段
- 资产清单变更后，历史 finding 的资产判定 **不自动延续**，须按当前清单复判
- 程序文件与本节冲突时，以程序文件为准（`web-vendor-rules.md` §9）
