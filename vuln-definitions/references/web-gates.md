# Web 挖掘门禁（Gate T / S / E / C / R）

发现可疑点后 **按顺序回答**；任一「否」→ 不进入深度 PoC，最多记对内缺陷。

形态见 `web-vuln-types.md`；资产范围见 `web-asset-scope.md`；归类见 `classification.md`；调整与排除条款见 `severity-levels.md` §4 / §8、`classification.md` §4。

> **Gate 字母仅在本域内有效**（Web 用 `T` / `S` / `E` / `C` / `R`）。不要套用其它域的字母含义（OH 的 `A`–`D`、Chrome 的 `P` 等）。

---

## Gate T · 攻击者是谁？（威胁模型）

- [ ] **T1** 攻击者是：未认证 / 普通用户 / 同租户他人 / 跨租户 / **受限管理角色**（有管理角色，但对目标资源无权限）之一？写清哪一档
- [ ] **T1b** 受限管理角色成立否，看是否 **取得该角色之外的额外能力**：仅有店铺管理权却获得服务器命令执行属成立（同 `rce.md` 的 SSTI 示例）；角色内本就允许的运维操作不成立
- [ ] **T2** 不需要：物理接触、已持有等价权限、管理员主动误配置？
- [ ] **T2b** 若需受害者动作，区分两种：**自行运行攻击者提供的程序**（不成立）vs **正常使用已有工具解析攻击者可控工件**（成立，按 `ci_runner` / `dev_tool` 计，见 `web-asset-scope.md` §3）
- [ ] **T3** 不依赖未证明的第二个缺陷才产生安全含义？
- [ ] **T4** 影响大于攻击者已有能力（能读自己数据的用户再读自己数据不算）？
- [ ] **T5** 仅影响攻击者自身账号 / 自伤 → 不报（`severity-levels.md` §4）

## Gate S · 是不是合格资产？

对照 `web-asset-scope.md`（程序文件优先）。

- [ ] **S1** 属合格分桶（`core_web` / `console` / `api_gateway` / `static_frontend` …）且不在范围外清单？
- [ ] **S2** 不是第三方责任边界（支付、采购 SaaS、CDN 默认页、状态页、文档站）？
- [ ] **S3** 未列出资产已写明判定依据（`unlisted` 不自动合格）？
- [ ] **S4** 涉多域时写清影响域（cookie 域继承、脚本加载域、接口域）？
- [ ] **S5** 多租户已写清边界（普通用户 / 同租户他人 / 跨租户）？
- [ ] **S6** 已记 `web_asset` 与 `web_scope`（见 `shared/finding-schema.md`）？

## Gate E · 环境合格吗？

- [ ] **E1** 复现发生在 **生产**，或命中 `severity-levels.md#ADJ-E1`（预发 / 灰度 / DEV 与生产同构）？
- [ ] **E2** 仅 mock 数据或鉴权链路不同 → 按 `#ADJ-E2` 降一档，已在 `rationale` 写明？
- [ ] **E3** 仅本地开发环境且无公网可达 → 不报（`#ADJ-E3`）？
- [ ] **E4** 不依赖已修复版本中的临时状态（绕过已修缺陷走 `#ADJ-B1`，不沿用原档）？
- [ ] **E5** 测试流量与目标程序纪律一致（限速、只用自有账号、不触碰他人数据）？

## Gate C · 有没有「安全实害」？

至少命中一条，且能演示：

| 实害类型 | 合格例子 | 不合格例子 |
|----------|----------|------------|
| 代码执行 | 可控输入直达命令 / 模板 / 反序列化 sink | 仅报错栈显示内部路径 |
| 数据访问 | 读他人 / 跨租户数据；全量可遍历 | 只读低敏元数据且无后续利用 |
| 身份与凭据 | 取得会话 / 凭据，或伪造他人身份 | 密码策略弱（需管理员配合） |
| 资金与权益 | 可复现的资金损失或配额逃逸 | 前端展示层限制而服务端不可绕 |
| 客户端执行 | 在他人会话执行脚本或驱动敏感操作 | 仅自身会话可见的 self-XSS |
| 云与运行时 | 拿到云凭据、跨用户容器读写 | 仅内网存活探测 |

- [ ] **C1** 危害写清到「谁、越过哪条边界（会话 / 租户 / 权限 / 网络 / 执行环境 / 完整性）、拿到什么」
- [ ] **C2** 数据面已按 `severity-levels.md` §7 矩阵给出 `data_scale` × `data_sensitivity`
- [ ] **C3** 有可观测证据（回显 / OOB / 状态变化 / 跨会话差异），不是「可能」
- [ ] **C4** 不属排除项（纯 DoS 与资源耗尽、缺安全头、版本披露、扫描器输出、纯理论）

## Gate R · 能否复现并合格投递？

- [ ] **R1** 白盒有 source→sink 路径；黑盒有分步请求序列与响应差异
- [ ] **R2** PoC 最小化、可独立复跑（无未说明的前置状态）
- [ ] **R3** 链路类已给出 **终态** 证据；未证实终态时按 `#ADJ-C1` 落到「链前半段 → high」
- [ ] **R4** 修复绕过已填 `regression_of`，多次复报按 `#ADJ-B2` 合并（完全重复填 `duplicate_of`）
- [ ] **R5** `severity_rule` 填的是本插件内的真实条款号（`<type>.md#<等级>` 或 `severity-levels.md#ADJ-…`）
- [ ] **R6** 发现敏感个人数据或凭据 → 停止深入、按目标程序流程立即上报

---

## 门禁结论

| 结果 | 动作 |
|------|------|
| T / S / E / C / R 全过 | 进入定级，按类型条款匹配 C → H → M → N |
| S 不过 | 不报（`web_scope: out_of_scope`） |
| C 不过 | 不报，或按 `severity-levels.md` §4 记 `none` 并写否决原因 |
| E1 不满足但 E2 满足 | 降一档后定级 |
| R3 未证实终态 | 按 `#ADJ-C1` 落在 high，并在 `chain_terminal_severity` 记 null |
