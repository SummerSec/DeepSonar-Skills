# ssrf — 服务端请求伪造定义

## 1. 漏洞定义是什么

**SSRF（Server-Side Request Forgery）**：攻击者诱使 **服务器** 向攻击者指定或可影响的目标发起 HTTP/其它协议请求，从而访问攻击者本不能直连的资源（内网、云元数据、本机服务等）。

**成立必要条件**：

1. 服务端存在出站请求能力  
2. 目标地址/协议/路径有攻击者可控成分  
3. 限制不足（无严格白名单、可改 host、可跳转、可 DNS rebinding 等）  

常见入口：webhook、URL 预览、导入、抓取、PDF/图片渲染、代理 API。

---

## 2. 严重（Critical）

| # | 判定条件 |
|---|----------|
| C1 | 可访问 **云 metadata**（如 `169.254.169.254`）并 **读出有效临时凭证** |
| C2 | 通过 SSRF 打到内网管理面并 **完成 RCE/接管**（有证据） |
| C3 | 可对内网 **Redis/未授权 DB/admin** 等执行导致沦陷的操作 |
| C4 | 可读本机 **敏感文件**（`file://`）含密钥/生产配置并证明内容 |

---

## 3. 高危（High）

| # | 判定条件 |
|---|----------|
| H1 | 可稳定访问 **内网 HTTP 服务** 并读取非公开响应（端口扫描+正文） |
| H2 | 可打 metadata 但 **仅部分字段** 或凭证利用未完成，已证明内网/链路层突破 |
| H3 | 可对内网发起请求造成 **高影响状态变更**（重启、加用户）有证据 |
| H4 | 绕过基础防护访问 **localhost 管理端口**，读取敏感配置页 |

---

## 4. 中危（Medium）

| # | 判定条件 |
|---|----------|
| M1 | 只能请求 **外网** 攻击者服务器（纯「服务器帮你出网」），无内网/metadata 证据 |
| M2 | 仅 DNS 查询/端口开闭探测， **无响应正文**、无敏感数据 |
| M3 | 协议/端口被很大程度限制，仅能访问少数 **低敏感** 内网页 |
| M4 | 需要管理员配置 webhook 且目标限制较多，影响限于自己租户噪音 |

---

## 5. 无危害（None）

| # | 判定条件 |
|---|----------|
| N1 | URL **严格域名白名单**（固定 allowlist）且无解析绕过 |
| N2 | 用户只能选 **预设枚举 ID**，服务端映射真实 URL |
| N3 | 客户端（浏览器）请求被误认为 SSRF |
| N4 | 出站请求目标完全写死在配置，用户不可控 |
| N5 | 开放重定向在浏览器中发生，不是服务端发起（归其它类） |

---

## 6. 白盒 / 黑盒证据要点

| | 白盒 | 黑盒 |
|--|------|------|
| 最低 | 用户 URL → HTTP client | 回调到 OOB / 不同响应证明打到内网 |
| Critical | 无阻拦 + 可 metadata 路径 | 读出 metadata 凭证明文 |
| none | `allowed_hosts` 校验正确 | 仅外网 echo 无内网 |
