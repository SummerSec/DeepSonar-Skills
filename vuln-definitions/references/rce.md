# rce — 远程代码执行定义

## 1. 漏洞定义是什么

**远程代码执行（RCE）**：攻击者通过网络入口 **或不可信工件入口**，使目标系统执行 **攻击者指定的代码或系统命令**（或等价：加载攻击者控制的字节码/脚本/表达式并求值）。

> **执行位置不是分类轴**：RCE 发生在服务端、CI 扫描节点、开发者本机（CLI / 桌面端 / IDE 插件）均归本类；位置只影响攻击前提与档位（见 `severity-levels.md` §5）。

本类型覆盖：

| 子类 | 示例 | CWE |
|------|------|-----|
| 直接代码执行 | `eval` / `exec` / `Function` / `ScriptEngine` | CWE-94/95 |
| 模板注入致 RCE | SSTI 出 `os.system` | CWE-1336 |
| 表达式注入 | SpEL / OGNL / EL | CWE-917 |
| 反序列化致 RCE | 见 deserialization（可交叉） | CWE-502 |
| 危险动态加载 | 用户控路径的 `require`/插件加载执行 | CWE-829 |
| 工件解析 / 符号执行自噬 | **被检工件**（仓库、PR、模型、配置、测试样本、插件包）的内容被拼入 `eval` / 表达式引擎 / 模板求解器执行 | CWE-95/116 |

**成立必要条件**：

1. 网络入口（含认证后接口）**或不可信工件入口**可达；工件入口指平台 / 本地工具会主动拉取并解析的攻击者可控内容（提交的仓库或 PR、上传的模型与配置、测试样本、插件包、锁文件与构建产物）
2. 执行语义由攻击者影响（影响方式允许经 **模型回显 / 持久化配置 / 队列转发** 等二跳通路，须证明通路可达，不限于直达输入）  
3. 能运行 **非开发者预定** 的逻辑（不只是选预设枚举）  

**不覆盖（边界）**：

- 只读数据、不能执行代码的注入 → `injection.md`
- 反序列化的解析/类型缺陷（未到执行）→ `deserialization.md`
- 需先具备管理员身份且无绕过的执行能力 → `authz.md`，或按 `severity-levels.md` 判无危害
- 浏览器 / WebView 内的脚本执行（XSS / UXSS / `postMessage`）→ `client-side.md`；本类只取「引擎进程被工件驱动执行任意命令」这一层

## 2. 严重（Critical）

| # | 判定条件 |
|---|----------|
| C1 | **未认证** 即可 RCE |
| C2 | **任意注册/普通用户** 即可 RCE（公网或广泛暴露的应用） |
| C3 | RCE 发生在 **生产核心服务**，可横向或直接触达密钥/数据库 |
| C4 | 沙箱 **可逃逸** 到宿主机/节点，影响集群 |

**示例**：未授权模板预览 SSTI 执行命令；公开 API `pickle.loads` 用户 body；**扫描引擎把被检源码的字符串常量拼入 `eval`，提交恶意仓库即可在扫描节点执行命令**（工件自噬形态，见上表末行）。

---

## 3. 高危（High）

| # | 判定条件 |
|---|----------|
| H1 | 需要 **特定已授权角色**（如运营、商家）才能 RCE，但该角色可自助注册或易获取 |
| H2 | 仅 **管理后台** RCE，后台暴露在公网或弱口令/可被其他漏洞进入 |
| H3 | 可执行代码但受限（容器无特权），仍可读环境变量/挂载密钥、打内网 |
| H4 | 代码执行证据充分，差一步出网/交互 shell，但已 `id`/写文件成功 |

**示例**：仅店铺管理员可编辑邮件模板导致 SSTI RCE；内网 admin 的脚本控制台公网误暴露。

---

## 4. 中危（Medium）

| # | 判定条件 |
|---|----------|
| M1 | 仅在 **本地/严格内网** 且无跳板路径的调试开关，需已持有 VPN+管理员 |
| M2 | 「代码执行」只能跑 **预设白名单脚本名**，不能插入任意语句 |
| M3 | 表达式沙箱 **未证明逃逸**，只能做算术/只读安全 API |
| M4 | 需链式多个未证明条件（如先拿 admin + 再开危险开关） |

---

## 5. 无危害（None）

| # | 判定条件 |
|---|----------|
| N1 | 动态执行的内容 **完全来自开发者静态资源**，用户不可控 |
| N2 | 使用安全沙箱且只暴露无害能力，审计确认无法逃逸 |
| N3 | 死代码/未启用 feature flag，生产构建剔除 |
| N4 | 客户端（浏览器）JS 执行不等于服务端 RCE；但 **CI 节点 / 本机工具被工件驱动执行命令** 仍属本类（不因“不在服务端”降为 none） |
| N5 | 合法插件机制：仅管理员装 **已签名** 包，符合产品设计（除非签名可绕过） |

---

## 6. 白盒 / 黑盒证据要点

| | 白盒 | 黑盒 |
|--|------|------|
| 最低 | 用户输入（含经模型输出、存档配置、队列消息等 **二跳源**）进入 eval/模板/表达式引擎，且完成白盒「通道 → 转发 → sink」闭环确认 | 执行 `whoami`/`id` 或写可控文件；二跳通路须附 **任一可归因证据**：白盒数据流、执行输出回流、OOB 回调、受控状态变化、时延基线（逐字回显一致性只是反射链的一种证法，不作为通用门槛） |
| 工件自噬 | 工件内容 → 反序列化/常量折叠/求解器 → `eval`，且无沙箱隔离 | 提交含特制常量的仓库/样本，扫描时回调 OOB 或落文件 |
| Critical | 路由无鉴权 + 危险 sink | 未登录复现 |
| none | 模板仅静态文件名 include | 只返回模板语法错误无执行 |
