# OpenHarmony 系统漏洞定级规则

本文件为 **系统类（OpenHarmony / 类移动 OS）审计** 的定级规则。  
审计目标为 OH **标准系统（standard）、小型系统（small）、轻量系统（mini）** 的 **系统服务层、框架层、应用层** 时，优先以本文件条款定级；与 `severity-levels.md` / `<type>.md` 冲突时，**系统语义以本文件为准**。

> 语义基线：OpenHarmony 安全漏洞奖励计划（官方口径，2026-05 版本）。  
> 漏洞**形态**按 Phone OS 共性覆盖（见 `vuln-definitions-oh` / `phone-os-vuln-types.md`），不局限单一厂商历史披露。

---

## 1. 何时使用

- 目标是 OpenHarmony 单设备（含分布式设备场景）
- finding 涉及：内核/驱动、IPC/SA、沙箱、权限与令牌、导出组件与 deeplink、媒体/消息、WebView/运行时、无线与分布式、安装/锁屏、广播/剪贴板等 Phone OS 通用面
- 需要对照官方「严重/高危/中危/低危」四档裁定等级，或判断是否会被判无效

---

## 2. 术语（官方）

| 术语 | 定义 |
|------|------|
| 远程 | 不安装应用、不实际接触设备即可利用（网页、短信/彩信、邮件、文件下载、无线网络通信等）。**同网 / 局域网 / 分布式组网报文算远程，不是本地** |
| 本地 | 需在受害系统安装应用，或需物理接触设备 |
| TCB | Trusted Computing Base：内核及驱动，或等同内核的用户服务（如 init、vold） |
| 特权进程 | SELinux `system_app` 域中运行的应用/进程；以 system 级权限运行的进程；root 进程 |
| 普通应用进程 | 第三方应用进程，或内置但无 system 级权限的应用进程 |
| 受限进程 | 比普通应用进程受更严格权限约束的进程 |

---

## 3. 四档危害（官方条款）

> 官方四档为 严重/高危/中危/**低危**；本仓报告模型为 critical/high/medium/none。  
> 官方「低危」仍可领奖（≤1 万元），但本仓默认按 **none（不报告）** 处理——语义上仍是「真实但低影响」。

| 档 | 本仓映射 | 一句话 |
|----|----------|--------|
| 严重 | `critical` | TCB 级沦陷 / 远程永久砖机 / 特权数据未授权读取 |
| 高危 | `high` | 普通应用远程 RCE / 隔离绕过 / 远程未授权读受保护数据 / 静默装包 |
| 中危 | `medium` | 受限进程远程 RCE / 本地各档 RCE / 本地未授权读受保护数据 / 不安全加密泄露 |
| 低危 | `none`（官方 low） | 本地受限进程 RCE / 本地临时 DoS / 低敏感信息泄露（官方原文：`低风险的信息泄露`） |

### 严重（Critical）

| # | 判定条件 |
|---|----------|
| C1 | 在 TCB 中 **远程执行任意代码** |
| C2 | 通过本地在 **特权进程或 TCB** 中执行任意代码，且 **能绕过内核消减措施** |
| C3 | 远程发起 **永久性 DoS**：设备无法再使用，或需重刷整个系统才可恢复 |
| C4 | 远程绕过应用安装及部分用户交互要求 |
| C5 | 在未鉴权情况下远程访问受保护数据，达到 **特权进程访问任意数据** 的效果 |
| C6 | 分布式设备场景下，在设备 **授权前** 跨设备远程代码执行 |

### 高危（High）

| # | 判定条件 |
|---|----------|
| H1 | 本地在 TCB 中执行任意代码 |
| H2 | 在 **普通应用进程** 中远程执行任意代码 |
| H3 | 绕过将应用数据与其他应用隔离开来的安全机制 |
| H4 | 绕过将用户或个人资料彼此隔离开来的安全机制 |
| H5 | 未鉴权情况下 **远程** 访问受保护数据（普通应用可访问的数据） |
| H6 | 本地永久性 DoS：设备需重刷操作系统或恢复出厂才可使用 |
| H7 | 远程暂时性 DoS：导致远程挂起或重新启动设备 |
| H8 | 无需用户交互 **远程** 开启/关闭通常需用户发起的功能 |
| H9 | 绕过屏幕锁（合成生物识别数据的绕锁不在范围） |
| H10 | 本地绕过用户交互实现 **静默安装** |
| H11 | 分布式：在控制 **弱设备** 的情况下，实现对 **富设备** 的远程代码执行 |

### 中危（Medium）

| # | 判定条件 |
|---|----------|
| M1 | 在 **受限进程** 中远程执行任意代码 |
| M2 | 通过本地在特权进程、预置应用中执行任意代码 |
| M3 | 通过本地在普通应用进程中执行任意代码 |
| M4 | 绕过特权进程/TCB 中的缓解技术（若直接导致任意代码执行或关键信息泄露，可酌情提升） |
| M5 | 未鉴权情况下 **本地** 访问受保护数据（需请求权限才可访问，或仅限特权进程访问的数据） |
| M6 | 无需用户交互 **本地** 开启/关闭通常需用户发起的功能 |
| M7 | 不安全的加密算法及密钥存储，可导致敏感信息泄露 |

### 低危（Low → 本仓 none）

| # | 判定条件 |
|---|----------|
| L1 | 通过本地在受限进程中执行任意代码 |
| L2 | 本地暂时性 DoS：系统挂起或设备重启 |
| L3 | 低敏感信息泄露（官方原文：`低风险的信息泄露`） |

## 4. 级别调整（命中即下调或判无效）

| # | 条款 | 对本模块含义 |
|---|------|--------------|
| ADJ1 | 漏洞已有消减措施且无法绕过 | SELinux/MAC 挡死 → 不报「DAC 宽」 |
| ADJ2 | 安全影响有限 | lite-only、非核心组件、非敏感数据 → 默认不跟 |
| ADJ3 | 特权依赖 / 物理接触 | 必须先 native/SA/root/**system UID** → 直接判无效 |
| ADJ4 | 利用场景极小概率 | 过期证、特殊时序、极窄配置、**须再叠未证明洞 / SA 中继半链** → 不跟 |
| ADJ5 | 默认配置或选项造成隐患 | **默认弱才算**；App 主动 `skip` 不算 |
| ADJ6 | 需解锁 bootloader 才能本地攻击 | 不作为主利用路径 |
| ADJ7 | 需开发者模式 / Debug 模式才能本地攻击 | 不作为主利用路径 |
| ADJ8 | 编译器或平台配置缓解了相应机制 | 缓解存在 → 按能否绕过定级 |
| ADJ9 | 获得的信息为对应权限范围内的部分信息 | 可报但预期降档（如「是否已授权」状态） |
| ADJ10 | 规格下无任何应用/服务被授该权限 | “缺校验”若规格本不允许任何调用方 → 不算洞 |

## 5. 无效漏洞（官方明文，命中即停）

| # | 条款 |
|---|------|
| INV1 | 无外部攻击路径：仅能由系统自身或提交人主动触发（自攻击/自触发） |
| INV2 | 没有安全影响的软件功能性错误（含中继半链、无完整攻击路径） |
| INV3 | 利用依赖钓鱼、诱导点击等欺骗用户的内容 |
| INV4 | 主要影响第三方/通用协议（应投对应渠道；OH 默认路径可独立演示实害时可例外） |
| INV5 | 上报前技术细节已公开（网站/自媒体/邮件组/公开演讲/即时聊天群等） |
| INV6 | 重复提交（仅首个报告有效） |
| INV7 | 权限等价：利用所需权限本身即可造成同等效果 |
| INV8 | 仅能通过本地触发导致应用临时拒绝服务 |
| INV9 | 其它应属无效漏洞的场景 |

**复现硬门槛**：最新公开版本 + **标准默认配置** 可复现；报告须人工验证 + 分步复现 + **完整可编译 PoC**。

## 6. Phone OS 类型与攻击面（摘要）

完整类型定义见 `vuln-definitions-oh` 的 **`phone-os-vuln-types.md`**（Android / iOS / OH 通用形态，不局限历史披露清单）。  
OH 组件索引见同插件 `attack-surfaces.md`；影响语映射见 `severity-levels.md` §6。

| 类型簇 | 例 | 条款倾向 |
|--------|-----|----------|
| 内核/驱动 TCB | 本地 UAF/越界 → ACE/root | H1 / C2；远程进 TCB → C1 |
| IPC / 系统服务 | 缺鉴权、混淆代理/中继、Parcel 内存破坏 | M5/H5/H3；半链 → ADJ4/INV2 |
| 沙箱/隔离 | 跨应用数据、路径穿越、多用户 | H3 / H4 |
| 权限/令牌 | 权限绕过、身份伪造 | M5/M6；远程 → H5/H8 |
| 导出组件/deeplink | 未鉴权导出、链接越权 | M5/H5 |
| 媒体/消息解析 | 畸形媒体远程 ACE | H2 / C1 |
| Web/运行时 | 引擎 RCE、JS 桥、Ark 内存破坏 | H2 / M2/M3 |
| 无线/分布式 | BT/Wi‑Fi/SoftBus、跨设备 | H2/H5/H7；C6/H11 |
| 安装/锁屏/密钥 | 静默装、绕锁、密钥导出 | H10/H9/M7 |
| 广播/剪贴板 | 敏感事件、跨应用剪贴板 | M5 |

须 system UID / 二次洞 / 纯上游无默认路径 → ADJ3 / ADJ4 / INV4。

## 7. 报告与定级纪律

- 定级前先跑 Gate 检查：**攻击者是谁 → 默认与可达 → 直接实害 → 利用链闭合**；任一不过 → 判 `none`/对内（详见 `vuln-definitions-oh` 的 `gates.md`）。
- finding 的 `severity_rule` 填本文件锚点，如 `openharmony.md#H5`、`openharmony.md#INV1`、`openharmony.md#ADJ3`。
- 报告至少写清：影响与根因（版本/模块/代码逻辑）、**恢复出厂后** 分步复现 + 截图、完整可编译 PoC（源码/依赖/构建说明）。
- 与 CVSS 的关系：本文件负责 **定性**；量化用 `vuln-scoring`（**默认 CVSS v3.1**，可按需 v4.0）。**不得**单独把 none/low 抬进正式报告。
- **不收录具体 case**：本文件只提供条款与判定规则，不写具体漏洞样例或历史漏洞清单。
