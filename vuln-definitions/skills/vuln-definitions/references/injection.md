# injection — 注入类漏洞定义

## 1. 漏洞定义是什么

**注入（Injection）**：应用程序将 **攻击者可控数据** 拼入或传入会被 **另一语言/引擎解释执行** 的上下文，导致查询、命令或过滤器的语义被篡改。

本类型覆盖：

| 子类 | 典型引擎 | 常见 CWE |
|------|----------|----------|
| SQL 注入 | SQL 数据库 | CWE-89 |
| 命令注入 | OS shell / 进程参数未分离 | CWE-78 |
| NoSQL 注入 | Mongo 等操作符/表达式 | CWE-943 |
| LDAP 注入 | 目录服务过滤器 | CWE-90 |
| 表达式/脚本注入（非完整 RCE 框架时） | 部分规则引擎 | CWE-94（边界见 rce） |

**成立必要条件（同时满足）**：

1. 存在攻击者可控输入（HTTP 参数、Header、文件、消息队列等）  
2. 该输入进入可解释上下文（SQL/shell/LDAP…）  
3. 防护不足（未参数化、未严格转义、未白名单）  
4. 语义可被改变（不只是字符串出现在日志里）  

若最终效果是 **任意系统命令/代码执行**，且入口就是命令/代码执行 API，可主类型标 **rce**；若入口是 SQL/`xp_cmdshell` 等，主类型可仍为 **injection**，impact 写 RCE。

---

## 2. 严重（Critical）

满足 **定义**，且达到下列 **任一**：

| # | 判定条件 |
|---|----------|
| C1 | **未认证** 或 **任意普通用户** 可注入，并导致 **RCE / 读 OS 文件 / 写 webshell**（含 `INTO OUTFILE`、`COPY TO`、命令注入拿 shell） |
| C2 | 可 **整库拖取或任意写库**（含 DBA 权限等价），影响生产核心业务库 |
| C3 | 多租户场景下，注入可 **跨全部租户** 读/改数据 |
| C4 | 通过注入可 **关闭认证或创建管理员**（认证平面崩溃） |

**示例**：

- 登录框 SQL 注入直接 `UNION` 出全部用户哈希并登录任意账号，或 `'; users`  
- 诊断接口 `ping` 参数命令注入，公网可反弹 shell  
- 未授权导出接口 NoSQL 注入拖出全站用户 PII  

---

## 3. 高危（High）

满足定义，未达严重，但达到 **任一**：

| # | 判定条件 |
|---|----------|
| H1 | 需登录普通用户，可 **读取大量他人敏感数据**（订单、证件、令牌、消息）或 **修改关键业务数据** |
| H2 | 盲注/时间盲注可 **稳定抽取** 敏感库表内容（证明可自动化拖数） |
| H3 | 注入点权限较高（可写），虽未证明 RCE，但可改权限/支付/配置导致重大损失 |
| H4 | 内网高权限库可注入，且从外网应用 **稳定可达**（应用为入口） |

**示例**：

- 搜索接口 SQL 注入，登录用户可 UNION 出其他用户手机号/邮箱（规模大）  
- 订单查询注入可改任意订单状态/金额  

---

## 4. 中危（Medium）

满足定义，但影响有限：

| # | 判定条件 |
|---|----------|
| M1 | 只能读到 **当前用户本应可见** 或 **非敏感** 数据（如公开商品名） |
| M2 | 仅能造成 **报错/逻辑异常**，无法稳定外带敏感数据，也无写操作 |
| M3 | 注入存在但有 **强限制**（极短长度、强字符白名单部分绕过失败、只影响自己的一行非关键字段） |
| M4 | 仅 **开发/预发** 库，生产无此入口（若生产同步存在则按生产定级） |
| M5 | 二阶注入线索明确，但 **触发路径未证明** 或触发需极罕见操作 |

**示例**：

- `ORDER BY` 注入只能控制排序，无敏感数据、无堆叠查询  
- 报错显示 SQL 片段但无法 UNION/布尔盲注成功  

---

## 5. 无危害（None）

| # | 判定条件 |
|---|----------|
| N1 | 已使用 **参数化/预编译/ORM 安全 API**，用户输入不进语义结构 |
| N2 | 输入完全来自服务端可信源，攻击者不可控 |
| N3 | 危险字符串只出现在注释、文档、测试 fixture，生产不可达 |
| N4 | 扫描器 payload 触发 500，但证明是通用异常，**无语义注入** |
| N5 | 命令调用使用 **参数数组且无 shell**，用户输入不能改变 argv 结构（且无注入点） |
| N6 | WAF/中间层 **稳定阻断** 且应用层亦安全；仅 WAF 挡着而应用层可注入 → **仍算漏洞**（按可利用性定级，不因有 WAF 变 none） |

---

## 6. 白盒 / 黑盒证据要点

| | 白盒 | 黑盒 |
|--|------|------|
| 最低证据 | source 变量 → 拼接进 query/command | 可复现改变查询结果或命令副作用 |
| 升到 C/H | 无绑定参数 + 高权限 DB/OS API | 实际读出数据/执行 `id`/`whoami` 等价 |
| 常见 none | `query(sql, [userId])` 绑定正确 | 仅 `'` 导致语法错无进一步利用 |
