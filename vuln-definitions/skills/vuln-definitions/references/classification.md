# 漏洞归类规则

当一个问题可同时套多个类型时，按下列优先级 **只选一个主类型**（可在 impact 中注明关联类型）。

## 优先级（从高到低）

1. **rce** — 已证明或代码上直接可任意代码/命令执行  
2. **deserialization** — 根因是不安全反序列化（即便最终是 RCE，主类型仍可为 deserialization，或双标 rce 若利用面是通用 RCE 入口）  
3. **injection** — SQL/命令/LDAP/NoSQL 等注入语义  
4. **xxe** — 根因是 XML 解析外部实体  
5. **ssrf** — 根因是服务端请求伪造（即便读到文件，若经 file:// 且主因是 URL 控制，归 ssrf；纯路径遍历归 file-access）  
6. **file-access** — 路径遍历、任意文件读写、危险上传  
7. **authz** — 认证/授权/IDOR/会话  
8. **secrets** — 凭据泄露本身（若泄露导致的利用另开 finding）  

## 拆分 finding 的规则

- **根因不同** → 分开报（例如：硬编码 JWT 密钥 + 无鉴权管理接口 = secrets 一条 + authz 一条）  
- **同一根因一条利用链** → 报影响最大的一级，主类型取根因  
- **密钥泄露后可 RCE** → secrets（泄露）为主；RCE 作为 impact 描述，或另开 rce 若存在独立代码执行点  

## 不归入本仓类型的问题

| 现象 | 处理 |
|------|------|
| 反射/存储 XSS（无高权限会话窃取链） | 本仓默认 **不建类型**；有明确管理员会话窃取且可接管时，可归 **authz**（会话劫持）或单独说明 |
| CSRF | 仅当可造成资金/权限/接管级状态变更时，归 **authz** 的「状态变更无凭证」子类；否则 none/medium |
| 开放重定向 | 单独通常 none/medium；能偷 OAuth token 时归 **authz** |
| DoS / 限流 | 默认 none（本仓不关注可用性） |
| 依赖 CVE 无调用点 | none |
