# secrets — 敏感凭据暴露定义

## 1. 漏洞定义是什么

**敏感凭据暴露**：本应保密的认证材料、密钥、令牌出现在 **攻击者可获取的位置**，且可能被用于冒充身份、解密数据或调用受保护 API。

包括：云 AK/SK、私钥、JWT 签名密钥、数据库密码、第三方 API token、会话密钥、Kubeconfig 等。

CWE-798、CWE-321、CWE-312。

**成立必要条件**：

1. 材料属于 **真实敏感凭据**（非 public client_id  alone）  
2. 暴露位置对攻击者 **可达**（仓库、前端包、接口、对象存储、日志）  
3. 具有 **滥用可能性**（有效或极可能有效）  

---

## 2. 严重（Critical）

| # | 判定条件 |
|---|----------|
| C1 | 暴露 **仍有效** 的云根凭证/高权限 IAM，可创建资源或读全盘密钥 |
| C2 | 生产 **DB 高权限账号** 密码有效可直连 |
| C3 | 可伪造 **全局 JWT/会话** 的签名密钥泄露（任意用户接管） |
| C4 | 支付/清算/短信等 **资金或大规模滥用** 类 token 有效 |
| C5 | CI/CD **可推生产** 的 token 有效（供应链沦陷） |

---

## 3. 高危（High）

| # | 判定条件 |
|---|----------|
| H1 | 有效密钥影响 **单一重要子系统**（对象存储读写、邮件、地图高额调用） |
| H2 | 私钥/证书可解密部分流量或伪造 **部分** 服务身份 |
| H3 | 管理员会话 token / 重置链接密钥泄露，可定向接管 |
| H4 | 密钥在公开前端/仓库中，**高度疑似有效**（格式正确+服务端使用同值），待轮换 |

---

## 4. 中危（Medium）

| # | 判定条件 |
|---|----------|
| M1 | 密钥已 **过期/撤销**，但暴露流程仍在，需防再发 |
| M2 | 仅 **低权限** 只读 token，数据面有限 |
| M3 | 内网配置面板展示密钥，需已持有 VPN+低权账号 |
| M4 | 日志打印 **半脱敏** token，利用价值有限 |

---

## 5. 无危害（None）

| # | 判定条件 |
|---|----------|
| N1 | 明确 **示例/文档** 假密钥（`AKIA...EXAMPLE`、`changeme`） |
| N2 | 仅 **public** 标识：OAuth client_id、publishable key（文档定义为可公开） |
| N3 | 密钥只在服务端环境变量，未进入仓库/响应/前端（正确做法） |
| N4 | 误报：随机高熵字符串但非凭据上下文 |
| N5 | 已验证对所有相关服务 **无效** 且无其它危害 |

---

## 6. 白盒 / 黑盒证据要点

| | 白盒 | 黑盒 |
|--|------|------|
| 最低 | 源码/配置中的凭据形态 + 使用点 | 响应/JS/.git/对象存储中的凭据 |
| Critical | 与生产部署配置一致 | 调用云 API/DB **验证有效**（在授权下） |
| none | `.env.example` 假值 | 文档示例 key |

> 验证有效性时遵守授权与最小化：优先格式/引用证明；破坏性调用禁止。
